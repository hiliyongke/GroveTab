## 2. 核心功能完成度评估

### 2.1 Tabs 模块 — 较完善 ✅

**已有能力：**
- 9 种视图模式（WindowView、GridView、KanbanView、TimelineView、TabGroupView、CompactView、BookmarkView、FrequencyView、DomainGroupView）
- 拖拽排序、批量操作、选择模式
- Tab 休眠（discard）释放内存
- 按域名批量关闭/休眠
- DomainGroupView 虚拟滚动（本次新增 ✅）

**缺失功能：**
- ❌ 标签页预览（hover preview）——竞品标配，GroveTab 缺失
- ❌ 标签页分组命名（仅支持 Chrome 原生 tab groups）
- ❌ 标签页固定过期自动取消固定

### 2.2 Bookmarks 模块 — 较完善 ✅

**已有能力：**
- 去重检测（strict/loose）、失效检测（HEAD 请求）
- 智能整理（按域名聚类）、空文件夹清理

**缺失功能：**
- ❌ 书签批量导入/导出（HTML/JSON）
- ❌ 书签嵌套层级管理可视化
- ❌ 书签搜索独立管理功能

### 2.3 Search 模块 — 完善 ✅

**已有能力：**
- 多引擎切换（Google/Bing/Baidu/DuckDuckGo 等）
- 拼音搜索支持、搜索历史、热词联想
- `tag:` 语法限定标签范围
- 本次新增 Web Worker 索引优化 ✅

**缺失功能：**
- ❌ 搜索结果顶部的"快速操作"快捷键提示
- ❌ 搜索历史自动分组/时间线展示

### 2.4 History 模块 — 完善 ✅

**已有能力：**
- 最近关闭（含整窗恢复）
- 操作时间线（tab 打开/关闭/归档/搜索等）
- 昨天→今天对比卡片
- 多维历史分析视图（每日趋势、小时热力、站点排行）
- JSON 导出

**缺失功能：**
- ❌ 按时间范围自动清理历史（TTL 配置）
- ❌ Chrome history 与插件历史的自动对账

### 2.5 Sessions/归档模块 — 较完善 ✅

**已有能力：**
- 会话创建、重命名、删除、合并
- 自动快照 + 手动归档
- 按时间筛选（今天/本周/本月/更早）
- 本次重构后接入了 Zustand sessions-slice ✅

**缺失功能：**
- ❌ 会话批量导入（用户无法从备份恢复）
- ❌ 会话分享（生成链接/导出给其他人）
- ❌ 会话版本历史（修改后能回滚）

### 2.6 Insights 模块 — 基础 ⚠️

**已有能力：**
- 近 7 天折线图、Top 10 域名柱状图
- 累计归档统计、使用频率 Top 5
- 存储配额监控（chrome.storage + OPFS）
- JSON 导出

**缺失功能：**
- ❌ 趋势预测（如"你通常在周三打开最多标签"）
- ❌ 自定义时间范围分析
- ❌ 洞察报告生成（PDF/图片格式）
- ❌ 高级图表（ECharts/D3）

## 3. 用户旅程缺口

### 3.1 首次使用 → 日常使用（缺口严重 ⚠️）

```
问题：Onboarding 过于简单（仅 OnboardingCard 组件）
```

**缺口：**
1. 首次使用没有引导教程（tooltip 引导）
2. 新用户不知道快捷键（Cmd+K 搜索、Alt+S 保存标签）
3. 没有"创建第一个工作区"的引导流程
4. 快速入门（SpeedDial）仅在首次显示，之后无入口

**改进建议**：增加渐进式 tooltip 引导，覆盖核心功能 + 快捷键提示

### 3.2 日常使用 → 归档整理（缺口中等 ⚠️）

```
问题：缺乏主动整理提示
```

**缺口：**
1. 没有"标签页过多"预警（超过 20 个 tab 时没有主动建议归档）
2. `TidySuggestionBar` 存在但触发条件不明确
3. 自动快照依赖用户手动触发，没有基于活动状态的智能快照
4. 从活跃 Tab 到归档会话的流程不够顺畅

### 3.3 归档整理 → 归档复用（缺口中等 ⚠️）

```
问题：归档后难以重新找到和恢复
```

**缺口：**
1. 归档列表按时间排序，缺乏标签/搜索功能
2. 没有"最近恢复的会话"快捷入口
3. 归档会话恢复后，被恢复的标签页不会自动标记来源会话

## 4. 数据能力缺陷

### 4.1 存储架构问题 ⚠️（严重）

```
chrome.storage.local 限制：
→ 单个 key 上限 10MB
→ 总容量约 10MB（实际更少）
→ 大型归档会话（大量标签）容易触发配额瓶颈
→ 没有分层存储（热数据/冷数据分离）
```

**证据（`/src/repositories/storage-repo.ts`）：**
- 所有数据默认走 `chrome.storage.local`
- OPFS 仅用于 video-storage 和热榜缓存，未用于核心数据
- sessions-slice 注释写道："存储路由仍由 ArchiveService 管理"

**影响：**
- 用户大会话（100+ 标签）存储失败
- 无法支撑长期使用的数据累积
- 同步架构无法基于当前存储构建

### 4.2 数据能力矩阵

| 功能 | 当前状态 | 缺失 |
|------|---------|------|
| 数据导出 | JSON 文件下载 ✅ | 无 HTML/CSV 格式 |
| 数据导入 | ❌ 完全不支持 | 缺少批量导入接口 |
| 数据可视化 | 基础 SVG 图表 | 无 ECharts/D3 |
| 数据分析 | 基础 Top N 统计 | 无自定义指标/漏斗分析 |
| 数据备份 | 手动单次导出 | 无自动定期备份机制 |

## 5. 跨设备同步 — ❌ 完全缺失

**证据：**
1. `manifest.json` permissions 中无 `chrome.storage.sync`
2. 所有 store 都使用 `chrome.storage.local`
3. 无任何 `sync`、`displayId`、`extensionId` 关联的跨设备逻辑
4. `sessions-slice.ts` 注释明确写道："存储路由仍由 ArchiveService 管理"

**影响：**
- 企业用户强需求无法满足（这是企业级产品的核心需求）
- 用户换设备后所有数据丢失
- 团队协作基础条件缺失

**技术建议：**
- 短期内：先完善导入/导出，让用户可以手动迁移数据
- 中期：评估 `chrome.storage.sync` 是否够用（6MB 限制可能不够）
- 长期：考虑自建同步服务或基于云函数的方案

## 6. 团队协作 — ❌ 完全缺失

**证据：**
- 代码中无任何 `collaborat`、`team`、`shared`、`share` 关键词
- `Workspace` 类型仅包含个人过滤条件
- 无任何 HTTP 请求相关的数据共享逻辑

**缺失功能：**
- ❌ 工作区/会话分享给团队成员
- ❌ 标签共享（部分竞品支持）
- ❌ 团队成员查看他人会话列表
- ❌ 权限管理（owner/editor/viewer）

---

## 7. AI 智能化 — ❌ 几乎为空白

**已有智能化（极其基础）：**
- `useSmartSuggestions`（仅根据存储配额、使用频率给出提示，非 AI）
- `BookmarkAutoRuleModal`（简单的自动规则，基于固定规则非智能推断）

**缺失的 AI 能力：**

| 功能 | 描述 | 竞品状态 |
|------|------|---------|
| 智能分组 | 自动将相似标签页归为一组 | Tabout 测试版 |
| 智能推荐 | 根据访问模式推荐可能需要的标签页 | 无 |
| 智能摘要 | 为长会话自动生成描述/标题 | 无 |
| 自然语言搜索 | "找上个月看过的那篇关于 AI 的文章" | 无 |

## 8. 移动端 — ❌ 完全不支持

**证据：**

- 代码中无响应式布局优化
- 无 Android/iOS 平台声明
