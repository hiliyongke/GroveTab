# 07. 热榜聚合模块独立报告

模块范围：`trending` + `services/trending-service.ts`，覆盖 18 个平台的热榜聚合、分类筛选、紧凑布局、单榜刷新、全量刷新、本地缓存和“偷摸模式”。

市场数据快照（Chrome Web Store，2026-05-25）：

| 产品      | 用户量 | 评分 | 评论数 | 主要定位                        |
| --------- | ------ | ---- | ------ | ------------------------------- |
| daily.dev | 400K   | 4.82 | 2,798  | 开发者内容流 / 新标签页内容分发 |
| 稀土掘金  | 100K   | 3.47 | 352    | 中文开发者内容入口              |
| Momentum  | 2M     | 4.49 | 13,759 | 新标签页内容 / 习惯养成         |
| Tabliss   | 100K   | 4.66 | 382    | 新标签页展示与个性化承载        |

结论：当前热榜模块可用性合格，作为新标签页里的副空间足够轻快，18 个平台覆盖也有一定广度；但它本质上仍是“单源 API 聚合页”，不是“有分发逻辑、有沉淀路径、有内容质量控制的内容入口”。与 daily.dev 相比，Canopy 的差距主要在源治理、个性化和后续行动链路。

## 1. 功能完善度评估

完成度评分：61/100。

- 当前版本已经具备基础消费闭环：分类、卡片、单榜刷新、全部刷新、缓存、失败回退和紧凑布局都有，适合轻量浏览热点。
- “偷摸模式”是一项有记忆点的差异化交互，但它更偏趣味 / 场景化防打扰，不是核心内容能力。
- 数据覆盖面不算差：当前服务层配置了 18 个平台，含综合、科技、娱乐、社区和新闻，至少解决了“多站点切换麻烦”的问题。
- 当前最大短板是单源依赖：热榜数据几乎完全依赖一个第三方 API 入口，源稳定性、字段一致性和更新时效都存在较高外部风险。
- 当前次要短板是用户沉淀链路弱：用户看完榜单后只能跳转外链，没有“稍后读”“收藏到工作区”“加入归档/书签”的强后续动作。
- 当前模块缺少个性化排序与质量治理：所有用户几乎看到同样内容，系统无法基于本地兴趣和近期行为给出更高质量的前排结果。

## 2. 对标主流竞品的核心能力欠缺与短板

- 对标 daily.dev，Canopy 缺少“个性化内容分发层”。daily.dev 的竞争力不只是内容源，而是围绕开发者兴趣做筛选和排序；Canopy 目前更像统一入口，没有本地推荐能力。
- 对标稀土掘金，Canopy 缺少“内容深链接与上下文”。当前只展示热榜标题，缺少摘要、标签、来源质量提示和收藏转化路径。
- 对标 Momentum / Tabliss，Canopy 的热榜模块还没有和新标签页整体节奏充分融合。它是一个可访问的二级空间，但不是用户愿意每天停留的核心首页。
- 当前缓存策略不够强：虽然有本地缓存，但缺少多源回退、源健康探测、缓存可视化和缓存级别的质量控制。

## 3. 具体可落地的优化方向与改进建议

| 优先级 | 优化方向                 | Chrome / Web API                                                                | 具体可落地方案                                                                                                          | 预期收益                                         |
| ------ | ------------------------ | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| P0     | 从单源聚合升级为多源路由 | `AbortSignal.timeout()`, `URLPattern`, `Cache Storage`, `chrome.alarms`         | 为不同平台配置一级 API、二级抓取回退和本地缓存回退；用 `URLPattern` 管理源规则，用 `AbortSignal.timeout()` 控制慢源超时 | 显著降低单点依赖带来的不可用风险                 |
| P0     | 强化离线缓存和冷启动体验 | OPFS, `CompressionStream`, `scheduler.postTask()`                               | 榜单正文和摘要缓存落 OPFS，压缩后持久化；首屏先读本地缓存，再后台刷新；后台排序与渲染分片执行                           | 首次打开更稳、更快，断网场景仍可读               |
| P0     | 增加“内容沉淀”动作       | `chrome.bookmarks`, `File System Access API`, `navigator.clipboard.writeText()` | 热榜卡片新增“加入书签”“加入稍后看会话”“复制链接”“导出阅读清单”动作                                                      | 从纯浏览变成可操作入口，增强与主产品链路的联动   |
| P1     | 引入本地个性化排序       | `chrome.storage.session`, `scheduler.postTask()`                                | 记录用户点击平台、点击主题、停留时间和收藏行为，做完全本地的轻量排序权重调整                                            | 更接近 daily.dev 的个性化体验，但仍保持零账号    |
| P1     | 将热榜扩展为常驻伴随空间 | `chrome.sidePanel`                                                              | 在新标签页之外，提供 Side Panel 版热榜，让用户浏览网页时也能随手看榜和收藏                                              | 提高使用频率，弱化“只能在新标签页访问”的入口限制 |
