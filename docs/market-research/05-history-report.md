# 05. 历史记录模块独立报告

模块范围：`history` + `chrome/history.ts` + `repositories/history-repo.ts`，覆盖最近关闭、整窗恢复、插件操作时间线、日快照对比、关键词筛选和与浏览器 `history` 权限相关的历史建议能力。

市场数据快照（Chrome Web Store，2026-05-25）：

| 产品                     | 用户量 | 评分 | 评论数 | 主要定位                   |
| ------------------------ | ------ | ---- | ------ | -------------------------- |
| Better History           | 100K   | 4.70 | 1,428  | 浏览历史查询 / 删除 / 导出 |
| History Trends Unlimited | 60K    | 4.52 | 470    | 历史趋势分析 / 统计图表    |
| Session Buddy            | 1M     | 4.66 | 25,095 | 最近关闭 / 会话恢复        |
| Quick Tabs               | 30K    | 4.54 | 549    | MRU 导航 / 最近访问切换    |

结论：当前历史模块已经不是简单的“最近关闭列表”，而是把最近关闭、操作时间线和天级变化摘要放进了统一面板，方向正确；但与 Better History、History Trends Unlimited 相比，Canopy 记录的是“插件内历史”，还不是“浏览器级历史分析层”，深度和可追溯性都偏浅。

## 1. 功能完善度评估

完成度评分：67/100。

- 基础闭环已经形成：最近关闭、整窗恢复、操作时间线、关键词搜索、类型筛选、Undo 反操作和“昨天 → 今天”快照对比都已具备。
- 当前实现有明显的本地优先优势：大部分历史数据来自插件自身动作流，隐私边界清晰，且支持黑名单、TTL、容量上限和一键清理。
- 与多数标签页扩展相比，Canopy 已经把“误关恢复”场景做到了可用水平，尤其是 `ClosedWindowRecord` 和 UndoBus 设计，说明工程上考虑过真实高频误操作场景。
- 模块短板在“覆盖范围”而不在“是否可用”：当前更偏插件内行为记录，对浏览器原生历史、访问路径、访问强度和时间范围分析支撑不足。
- 模块短板在“结构维度”而不在“展示列表”：时间线当前以事件流为主，缺少按站点、按时间段、按访问链路、按来源类型的深度切片分析。
- 模块短板在“可迁移性”而不在“能否查看”：当前没有历史导出、对账、分段清理和审计能力，不利于形成长期分析资产。

## 2. 对标主流竞品的核心能力欠缺与短板

- 对标 Better History，Canopy 缺少“浏览器原生历史的深度操作能力”。Better History 的强项是按时间范围删、按域名筛、按关键词导出；Canopy 当前更像插件操作回放，不是历史治理工具。
- 对标 History Trends Unlimited，Canopy 缺少“趋势视角”。目前只有天级快照对比和局部统计，没有访问频次、时间分布、站点留存和长期趋势曲线。
- 对标 Session Buddy，Canopy 的“恢复链路”不错，但“回溯链路”较弱。用户能恢复刚关掉的标签，却很难顺着历史关系理解自己这几天到底看过什么、怎么切换的。
- 对标 Quick Tabs，Canopy 还没有真正把“最近活跃路径”转化为高效导航信号。当前更多是列表和事件记录，而不是 MRU 驱动的快速回跳系统。
