# 02. 搜索与命令中心模块独立报告

模块范围：`search`，覆盖搜索浮层、Tab 搜索、最近搜索、热门关键词、历史建议、最近关闭、网页搜索回退、自定义搜索引擎和键盘导航。

市场数据快照（Chrome Web Store，2026-05-25）：

| 产品                      | 用户量 | 评分 | 评论数 | 主要定位                  |
| ------------------------- | ------ | ---- | ------ | ------------------------- |
| Tab Manager by Workona    | 200K   | 4.64 | 3,795  | 工作区内全域搜索          |
| Session Buddy             | 1M     | 4.66 | 25,095 | 会话搜索 / 恢复           |
| Quick Tabs                | 30K    | 4.54 | 549    | MRU Tab Search / 快速切换 |
| Toby: Tab Management Tool | 300K   | 4.21 | 3,279  | 集合内组织与检索          |

结论：当前搜索模块已经是 Canopy 的高频入口之一，但本质上仍是“标签页搜索 + 网页搜索增强”，还不是“统一命令中心”。与 Workona、Quick Tabs 相比，最大差距不在 UI，而在索引范围、排序信号和动作密度。

## 1. 功能完善度评估

完成度评分：71/100。

- 输入体验成熟：支持键盘唤起、键盘导航、历史建议、热门词、最近关闭、网页搜索回退、自定义搜索引擎和拼音搜索，对中文场景适配优于大量国际化竞品。
- 当前检索对象仍以“实时标签”为主：虽然已经接入历史建议、最近关闭、网页搜索动作，但归档、书签、工作区、标签元数据和更多命令动作还没有进入统一结果集。
- 索引能力仍是轻量实现：当前以 MiniSearch 和运行时构建为主，适合中小规模数据，但不适合把归档、书签、OG 描述、行为事件全部纳入同一个索引平面。
- 语法能力不足：现有实现只实装了 `tag:` 局部语义，`site:`、`in:archive`、`has:note`、`pinned:true` 等高价值过滤尚未真正落地。
- 排序信号不足：当前更多依赖文本相关性和最近访问时间，尚未引入激活频率、会话命中率、工作区上下文、用户历史选择等更强信号。

## 2. 对标主流竞品的核心能力欠缺与短板

- 对标 Workona，Canopy 缺少“跨实体统一检索”。Workona 的搜索既能找 Tab，也能找空间、文档、任务和历史上下文；Canopy 目前还没有把归档、书签、工作区、动作统一为一个命令平面。
- 对标 Quick Tabs，Canopy 的“切换优先级”不够激进。Quick Tabs 强调最近使用（MRU）路径，因此“找回刚刚看过的页”非常快；Canopy 目前对 MRU 的利用还偏轻。
- 对标 Session Buddy，Canopy 缺少“离线会话索引”。当前归档搜索仍在归档页内部完成，没有融入主搜索，因此用户在搜索层面无法感知会话资产。
- 对标 Toby，Canopy 缺少“语义范围切换”的心智收敛。用户仍需知道自己是在找 Tab、归档还是网页，系统并没有真正帮用户吸收这些边界。

## 3. 具体可落地的优化方向与改进建议

| 优先级 | 优化方向               | Chrome / Web API                                                           | 具体落地方式                                                                                                                                               | 预期收益                                           |
| ------ | ---------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| P0     | 构建统一离线索引层     | `chrome.offscreen`, OPFS, IndexedDB, `CompressionStream`                   | 由 Offscreen Document 或 Worker 在后台把实时标签、归档、书签、备注、标签、OG 描述统一写入 OPFS/IDB 索引；用 `CompressionStream` 压缩快照，降低启动重建成本 | 从“即时搜索框”升级为“全域命令中心”                 |
| P0     | 正式落地查询语法       | `URLPattern`                                                               | 用 `URLPattern` 解析 `site:`、`in:`、`has:`、`pinned:`、`tag:` 等语法；把规则解析从字符串包含匹配升级为结构化查询                                          | 高阶用户检索效率大幅提升，搜索边界更清晰           |
| P0     | 输入优先级与超时治理   | `scheduler.postTask()`, `AbortSignal.timeout()`                            | 对搜索索引构建、历史请求、热词刷新使用低优先级任务和显式超时，避免主线程在输入时被搜索任务抢占                                                             | 复杂数据集下仍能保持输入流畅                       |
| P1     | 把“搜索”扩展成动作总线 | `chrome.commands`, `chrome.sessions`, `chrome.history`, `chrome.bookmarks` | 为“打开归档”“合并重复”“恢复最近关闭”“切到某工作区”“加书签”“打开历史面板”等动作建立命令结果项                                                               | 搜索成为全局入口，而不是单一查找器                 |
| P1     | 补强排序信号           | `chrome.tabs.onActivated`, `chrome.storage.session`                        | 记录最近激活、最近命中、最近执行动作等轻量会话信号，形成 MRU + 文本相关性混排；短期信号放 `storage.session`，长期统计走 IDB                                | 更接近 Quick Tabs / Workona 的“想找什么就出来什么” |
