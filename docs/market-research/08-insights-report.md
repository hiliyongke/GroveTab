# 08. 本地隐私洞察模块独立报告

模块范围：`insights` + `shared/utils/metrics.ts` + `sw` 中的 `StatsCollector`，覆盖近 7 天打开次数、Top 域名、累计归档、Top 操作和清空统计。

市场数据快照（Chrome Web Store，2026-05-25）：

| 产品                     | 用户量 | 评分 | 评论数 | 主要定位              |
| ------------------------ | ------ | ---- | ------ | --------------------- |
| History Trends Unlimited | 60K    | 4.52 | 470    | 浏览趋势统计          |
| Better History           | 100K   | 4.70 | 1,428  | 历史管理与回溯        |
| Tab Suspender by Workona | 30K    | 4.04 | 330    | 资源节省 / 挂起治理   |
| Tab Manager by Workona   | 200K   | 4.64 | 3,795  | 工作流管理 / 标签组织 |

结论：当前洞察模块已经迈出了正确一步，至少把“产品是否有本地数据能力”这个问题回答成了“有”；但它仍停留在轻量统计板阶段，数据维度、性能指标和建议能力都不够深。与 History Trends Unlimited 相比，Canopy 的差距主要在指标可信度和行动价值。

## 1. 功能完善度评估

完成度评分：56/100。

- 现有 4 张卡片结构合理：近 7 天打开次数、Top 域名、累计归档、Top 操作已经覆盖“频率”“对象”“收益”“行为”四个基本面。
- 模块最大优点是“全部本地计算、零上传”，这与 Canopy 的产品定位高度一致，也有利于建立隐私信任。
- 现有埋点架构具备继续扩展的基础：`MetricEvent` 事件流、`StatsData` 聚合表、SW 统计刷盘、清空入口都已存在，不是从零开始。
- 当前短板是指标深度不足：很多数据仍是计数型，而非分析型，例如“约节省内存”使用粗略乘数，并不反映真实设备与真实 Tab 占用。
- 当前短板是时间维度不足：除了近 7 天，没有更多时间窗、趋势分层、峰值时段和变化归因。
- 当前短板是建议能力不足：看板能“告诉用户发生了什么”，但不能“告诉用户该做什么”。

## 2. 对标主流竞品的核心能力欠缺与短板

- 对标 History Trends Unlimited，Canopy 缺少“高可信度趋势面板”。当前更像运营看板，而不是长期分析面板。
- 对标 Better History，Canopy 缺少“从数据到操作”的桥接。看到某个域名访问过多、某类操作过频，用户目前无法直接跳到治理动作。
- 对标 Tab Suspender by Workona，Canopy 的资源收益指标过于粗糙。当前只给出估算值，没有真实内存压力、挂起成效或设备上下文。
- 对标 Workona，Canopy 还没有把洞察转化为“工作方式建议”。例如没有告诉用户什么时候应该归档、哪些站点最适合固定、哪些工作区最活跃。

## 3. 具体可落地的优化方向与改进建议

| 优先级 | 优化方向                 | Chrome / Web API                                                                              | 具体可落地方案                                                                                                           | 预期收益                               |
| ------ | ------------------------ | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------- |
| P0     | 提升性能与资源指标可信度 | `PerformanceObserver`, `performance.measureUserAgentSpecificMemory()`, `chrome.system.memory` | 采集 `paint`、`longtask`、输入延迟和内存估算；结合 `system.memory` 获取设备级内存压力，再对归档 / 挂起收益做更真实的估算 | 把“约节省内存”从粗略口号升级为可信指标 |
| P0     | 增加本地存储与配额洞察   | `navigator.storage.estimate()`, `navigator.storage.persist()`                                 | 展示归档、主题素材、索引和统计各自占用；引导用户开启持久化存储并识别高风险配额状态                                       | 让用户知道数据占哪、风险在哪、该清什么 |
| P0     | 建立可导出的分析快照     | `File System Access API`, `CompressionStream`, OPFS                                           | 支持导出时间段内的统计快照、事件样本和性能摘要为 `.json.gz` / `.csv`                                                     | 洞察模块从“看看”升级为“可复盘、可审计” |
| P1     | 增加建议引擎             | `scheduler.postTask()`, `URLPattern`                                                          | 基于重复、闲置、访问频次、归档次数和站点分布，自动生成“建议固定”“建议建工作区”“建议定时归档”等本地建议                   | 洞察从被动展示变成主动优化入口         |
| P1     | 强化写入一致性与长期留存 | `Web Locks API`, `chrome.storage.session`                                                     | 高频事件先写 `storage.session` 做缓冲，后台聚合后以锁保护方式刷入长期仓库                                                | 减少并发写损坏和频繁落盘带来的抖动     |
