# 06. 设置与个性化模块独立报告

模块范围：`settings` 全模块，覆盖外观、行为、数据、隐私、快捷键、关于页、配置预设、背景图 / 视频、渐变、皮肤、视图布局和权限相关配置。

市场数据快照（Chrome Web Store，2026-05-25）：

| 产品                      | 用户量 | 评分 | 评论数 | 主要定位                 |
| ------------------------- | ------ | ---- | ------ | ------------------------ |
| Momentum                  | 2M     | 4.49 | 13,759 | 新标签页个性化 / 小组件  |
| Tabliss                   | 100K   | 4.66 | 382    | 高自由度新标签页定制     |

结论：当前设置模块覆盖面很广，已经具备成熟产品的参数厚度，尤其是外观、行为、隐私、快捷键和配置预设都不弱；但它仍然偏“配置集合”，还不是“有诊断能力、可预演、可恢复、可迁移”的设置系统。与 Momentum / Tabliss 相比，Canopy 的差距不在选项数量，而在体验闭环与上下文感知。

## 1. 功能完善度评估

完成度评分：76/100。

- 配置覆盖面较全：主题、皮肤、渐变、背景图、背景视频、动效、布局密度、UI 显隐、默认空间、默认视图、搜索行为、隐私历史、配置预设、导入导出和快捷键都已覆盖。
- 对高级用户友好：`skinCustom`、自定义搜索引擎、去重严格度、时间轴粒度、窗口视图参数等都说明设置模块不仅服务普通用户，也服务重度用户。
- “本地优先”实现较一致：大量设置直接落本地，且支持配置预设和一体化备份，符合产品本身的无账号定位。
- 当前短板不在“有没有设置”，而在“设置是否可理解”。大量高级参数虽已存在，但跨分组的解释、关联和推荐仍然不够强，普通用户容易迷失。
- 当前短板在“变更体验”而不在“存储能力”：很多外观和行为设置是实时落盘的，缺少临时预览、回滚和差异比较。
- 当前短板在“权限诊断”而不在“是否可申请权限”：例如 `history`、`bookmarks`、`<all_urls>` 等权限与对应功能之间的关系仍不够可视化。

## 2. 对标主流竞品的核心能力欠缺与短板

- 对标 Momentum 和 Tabliss，Canopy 缺少“所见即所得”的个性化体验。当前设置项多，但预览和即时反馈还不够强，用户需要脑补改动结果。
- 对标 Tabliss，Canopy 缺少“素材与主题的持久治理”。背景图、视频和复杂外观素材仍更多依赖 `storage.local` 路径，长期会碰到配额和恢复问题。
- 对标 Workona，Canopy 缺少“场景型配置”。虽然已有 profile，但还没有根据工作 / 学习 / 低性能机器 / 大量标签场景给出系统化预设策略。
- 对标成熟新标签页产品，Canopy 缺少“权限与能力的健康诊断视图”。用户知道有某个开关，但不一定知道它依赖什么权限、失败时为什么失败、当前状态是否生效。

## 3. 具体可落地的优化方向与改进建议

| 优先级 | 优化方向               | Chrome / Web API                                                                         | 具体可落地方案                                                                                                                     | 预期收益                                        |
| ------ | ---------------------- | ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| P0     | 引入设置预演与一键回滚 | `chrome.storage.session`, `View Transitions API`                                         | 外观与布局类设置先写 `storage.session` 作为临时草稿，用户确认后再落 `storage.local`；使用 View Transition 平滑展示主题切换前后差异 | 大幅降低试错成本，提升个性化调节意愿            |
| P0     | 做权限健康面板         | `chrome.permissions.contains`, `chrome.permissions.request`, `chrome.permissions.remove` | 在设置页新增“权限状态”区，逐项展示 `history`、`bookmarks`、`<all_urls>`、`tabGroups` 的当前状态、依赖功能和失败影响                | 减少“功能失效但用户不知道为什么”的摩擦          |
| P0     | 升级背景与主题素材存储 | OPFS, `navigator.storage.persist()`, `File System Access API`                            | 背景图、视频和大体量主题素材从 `storage.local` 迁到 OPFS，并请求持久化存储；支持本地文件重新绑定与目录级备份                       | 解决大素材占配额、恢复困难和长期可用性问题      |
| P1     | 增加智能取色与自动主题 | `EyeDropper`, `OffscreenCanvas`, `createImageBitmap`                                     | 用户可从背景图或屏幕取色器直接提取主色；用 OffscreenCanvas 从壁纸采样生成主题建议和对比度安全值                                    | 个性化更直观，也更接近 Tabliss 的“自由但不难用” |
| P1     | 强化配置预设迁移能力   | `File System Access API`, `CompressionStream`, `URLPattern`                              | 预设支持差异导出、批量导入、版本回滚和敏感字段排除；用规则校验旧版字段映射                                                         | 把 profile 从“小功能”提升为长期配置资产         |
