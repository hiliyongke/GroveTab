# 01. 标签工作台模块独立报告

模块范围：`workspace` + `tabs` + `quick-start`，覆盖首页工作台、实时跨窗口标签聚合、9 种实时标签视图、多选批量、整理建议、TabGroup/窗口/Kanban 组织方式和快捷站点层。

市场数据快照（Chrome Web Store，2026-05-25）：

| 产品                      | 用户量 | 评分 | 评论数 | 主要定位                     |
| ------------------------- | ------ | ---- | ------ | ---------------------------- |
| OneTab                    | 2M     | 4.45 | 14,527 | 极简会话收纳 / 省内存        |
| Session Buddy             | 1M     | 4.66 | 25,095 | 会话恢复 / 树状组织          |
| Tab Manager by Workona    | 200K   | 4.64 | 3,795  | 工作区 / 全域搜索 / 标签管理 |
| Toby: Tab Management Tool | 300K   | 4.21 | 3,279  | 集合式工作台 / 视觉化组织    |

结论：当前模块已经具备替代原生 Chrome 标签栏的基础能力，尤其在跨窗口聚合、多视图浏览和批量整理上已达中高完成度；但与 Workona、Session Buddy 相比，仍缺“常驻工作区 + 内存压力感知 + 会话级恢复保真”三项头部能力，因此产品天花板仍停留在“新标签页管理器”，还不是“浏览器级工作台”。

## 1. 功能完善度评估

完成度评分：78/100。

- 已形成完整主链路：新标签页接管、跨窗口实时聚合、域名/时间轴/紧凑/网格/频率/TabGroup/窗口/Kanban 等多视图、批量操作、Undo、闲置与重复整理建议都已落地。
- 交互层成熟度较高：支持快捷键、多选、批量归档、`chrome.tabs.discard` 休眠、窗口级操作、TabGroup 展示，说明模块不只是“列表展示”，而是已经具备操作台属性。
- 架构层基础较好：MV3 Service Worker 广播、Zustand slice 拆分、视图注册中心、懒加载拆包，意味着后续能继续扩展而不必推翻。
- 关键短板在“持久化工作区”而非“视图数量”：当前工作区更接近过滤器与视图切换器，缺少 Workona 那种空间实体、空间级生命周期和上下文留存。
- 关键短板在“内存治理精度”而非“是否支持休眠”：当前闲置检测主要基于时间阈值，缺少真实内存压力、CPU 状态、自动例外规则和关键 Tab 白名单策略。
- 关键短板在“恢复保真度”而非“是否能恢复”：当前更偏标签级恢复，尚未充分保留窗口结构、组结构、任务上下文，恢复后的心理连续性不如 Session Buddy 和 Workona。

## 2. 对标主流竞品的核心能力欠缺与短板

- 对标 Workona，Canopy 缺少“常驻工作区入口”。Workona 的核心价值不在于新标签页，而在于工作区可以持续伴随浏览过程；当前项目仍以新标签页为主入口，导致用户必须“回到工作台”才能管理，而不是“管理能力始终在手边”。
- 对标 Workona，Canopy 缺少“工作区实体化数据模型”。虽然当前已有 `WorkspaceSwitcher` 与基础工作区对象，但它更像筛选器雏形，没有空间级保存、关闭、恢复、上下文历史和空间内搜索闭环。
- 对标 Session Buddy 和 Tabs Outliner，Canopy 缺少“结构化恢复”。头部竞品会保留更多层级关系，例如窗口、组、时间序和树状上下文；当前项目更擅长当前态整理，但历史态复原的保真度还不够高。
- 对标 OneTab 和 Tab Suspender by Workona，Canopy 的“节省资源”叙事还不够硬。虽然已经有归档和 `discard`，但没有基于真实资源占用的自动策略，也没有清晰的内存节省面板和策略配置，因此“省资源”价值仍停留在感知层，而非数据层。
- 对标 Toby，Canopy 的视觉组织能力强于多数工具型扩展，但“集合/空间的沉淀能力”偏弱。当前 Kanban 更像视图，不是用户长期管理项目的容器。

## 3. 具体可落地的优化方向与改进建议

| 优先级 | 优化方向                     | Chrome / Web API                                                                                          | 具体落地方式                                                                                                                                                          | 预期收益                                                                  |
| ------ | ---------------------------- | --------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| P0     | 把工作台升级为常驻侧边工作区 | `chrome.sidePanel`, `chrome.commands`, `chrome.storage.session`                                           | 新增 Side Panel 入口，保留当前 New Tab 作为大屏总览；把当前选中视图、多选态、临时筛选态放入 `storage.session`，让工作区在新标签页、弹窗、侧边栏之间共享短生命周期状态 | 从“回到新标签页管理”升级为“浏览时随手管理”，直接补齐与 Workona 的入口差距 |
| P0     | 引入内存压力感知的自动治理   | `chrome.system.memory`, `chrome.tabs.discard`, `chrome.tabs.update({ autoDiscardable })`, `chrome.alarms` | 用可选权限 `system.memory` 建立低/中/高内存压力档位；对固定页、播放页、最近活跃页设置例外；对低价值标签自动建议 `discard` 或归档                                      | 把“闲置时间阈值”升级为“真实资源治理”，强化省资源叙事                      |
| P0     | 强化结构化恢复保真           | `chrome.sessions`, `chrome.tabGroups`                                                                     | 归档时记录窗口边界、组标题、组颜色、固定状态；恢复时优先按窗口和组重建，而不是仅按 URL 重开                                                                           | 与 Session Buddy 的核心差距会显著收敛，恢复后的心智连续性更强             |
| P1     | 优化大体量视图性能           | `scheduler.postTask()`, `PerformanceObserver`, `content-visibility: auto`, `View Transitions API`         | 把排序、去重、聚合等重计算降级到后台优先级；用 `PerformanceObserver` 监控 `longtask`；对非首屏卡片启用 `content-visibility`；用 View Transition 处理视图切换          | 500+ Tab 场景下更稳定，视图切换更平滑，避免“功能越多越卡”                 |
| P1     | 工作区实体化为可保存对象     | `File System Access API`, OPFS, `CompressionStream`                                                       | 把当前工作区筛选、布局、关键标签、恢复策略保存为本地工作区实体；支持导出 `.json.gz` 工作区快照到本地磁盘                                                              | 让 Kanban、窗口视图、筛选条件真正沉淀为长期可复用资产                     |
