# Phase 3 VERIFICATION — 域名分组视图

**Created:** 2026-04-22

> 本文根据 `.planning/ROADMAP.md` Phase 3 的成功标准,结合当前实现状态给出可执行的验证清单。

## 1. Roadmap 成功标准回顾

From `.planning/ROADMAP.md` Phase 3:

1. Tab 按注册域名正确分组,子域名合并
2. 分组间按 Tab 数降序,组内按最近激活降序
3. 折叠状态刷新后保持
4. 设置中可关闭接管

## 2. 验证项

> 初始均为 ☐,表示待人工验证。验证后可改为 ☑ 并补充说明。

### Check 1: 注册域名分组正确性

- **目标:** 对常见域名/子域场景(如 `a.google.com`, `docs.google.com`, `google.com`)进行分组,确认子域正确合并。
- **建议步骤:**
  1. 打开若干包含同一站点不同子域的页面;
  2. 打开 newtab 域名视图,观察是否合并为一个分组;
  3. 对比实际站点域名,确认无意外拆分或误合并。
- **状态:** ☐ 待确认
- **相关代码:** `src/shared/utils/domain.ts:1-84`

### Check 2: 分组与组内排序

- **目标:** 分组间按 Tab 数量降序,组内按最近激活时间降序。
- **建议步骤:**
  1. 打开多个域名的 Tab,人为控制每组的 Tab 数和最近激活顺序;
  2. 打开 newtab 域名视图,观察分组顺序是否符合预期;
  3. 点选不同 Tab 激活后返回视图,确认组内排序随 lastAccessed 更新。
- **状态:** ☐ 待确认
- **相关代码:** `src/shared/utils/domain.ts:57-84`, `src/store/tabs-slice.ts`

### Check 3: 折叠状态持久化(当前未实现)

- **目标:** 刷新页面后,折叠/展开状态保持不变。
- **当前状态:**
  - 代码中折叠状态仅使用组件内部状态管理,未持久化;
  - 刷新后会恢复默认状态,与 Roadmap 要求不符。
- **建议后续验证思路(待实现后):**
  1. 将若干分组手动折叠/展开;
  2. 刷新 newtab 页面;
  3. 检查折叠状态是否保持;
  4. 在 storage 中检查对应 key 是否存在且值正确。
- **状态:** ☐ 未实现(待补)

### Check 4: 设置中关闭 newtab 接管(当前 UI 未实现)

- **目标:** 用户可在设置面板中关闭 newtab 接管,并生效。
- **当前状态:**
  - 后端设置模型与存储已具备(`UserSettings.overrideNewTab`),但 UI 未暴露;
  - Roadmap 要求未完全满足。
- **建议后续验证思路(待 UI 实现后):**
  1. 打开 Settings 面板,找到 newtab 接管开关;
  2. 切换为关闭,重启浏览器或扩展;
  3. 打开新标签页,确认 Canopy 不再接管;
  4. 重新开启开关,确认接管恢复。
- **状态:** ☐ 未实现(待补)
